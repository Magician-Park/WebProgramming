학습 관심은 작성자가 지정한 AI, Data Science, App development입니다. 소개는 작성자가 지정한 문장입니다. 1주차는 첨부한 「[웹프로그래밍] Lec01. 오리엔테이션」 4~21쪽을 바탕으로 만든 학습 정리입니다. 2주차는 첨부한 「[웹프로그래밍] Lec02. HTML5 문서 기본」 2~44쪽의 학습 정리입니다. 3주차는 Lec03 PDF 2~19쪽의 링크·이미지 정리와 제공한 뉴스·웹툰 ZIP·코드 사진으로 확인한 실습 내용의 기록입니다. 4주차는 작성자가 확인한 추석연휴로 표시했습니다. 5주차는 Lec04 PDF 2~16쪽 CSS와 작성자가 배운 Git 작업 흐름을 공식 문서로 보완한 학습 기록입니다. 6주차는 Lec02 45~61쪽과 Lec05 전체를 바탕으로 만든 학습 기록입니다. 7주차 학습 페이지는 요청에 따라 작성한 예시입니다. 예시임을 화면에 표시했고, 본인의 실적이나 실제 수업 진도로 주장하지 않습니다. 배포 URL은 만들거나 지어내지 않았습니다.

## 주차별 문서 수정

1. 이력서의 1~3주차 또는 5~7주차 중 하나를 엽니다. 4주차 카드는 링크 없이 추석연휴로 표시합니다. 별도 week04.html에는 같은 안내를 남겼습니다.
2. **문서 수정**을 누르고 점선으로 표시된 제목·본문·표 내용·코드 예시를 클릭해 수정합니다.
3. **저장**하면 현재 브라우저에 보관되며, 같은 주차 페이지를 다시 열면 불러옵니다. **취소**하면 편집 시작 전 상태로 돌아갑니다.
4. 제출 소스에 반영하려면 **수정한 HTML 다운로드**를 누르고 내려받은 `week01.html` 등의 파일을 `practice/`의 같은 이름 파일과 교체합니다. `editor.js`, `practice.css`, 상위 폴더의 `style.css`와 `page-loader.js`는 함께 유지합니다.
5. 수정한 파일을 반영한 뒤 제출 ZIP과 REPORT, 캡처를 다시 갱신합니다. 편집 후 내용 검수와 W3C 재검사도 진행합니다.

브라우저 저장은 원본 파일이나 GitHub를 수정하지 않으며 다른 기기와 동기화되지 않습니다. 브라우저 데이터 삭제·주소 변경·비공개 모드·로컬 파일 정책에 따라 저장을 다시 읽을 수 없을 수 있으므로 제출할 내용은 HTML로 내려받으세요. 저장이 제한되면 안내가 표시되며 다운로드는 계속 사용할 수 있습니다. 8~15주차는 기존 ‘예정’ 상태로 유지했습니다.

## 페이지 이동 로딩 화면

이력서와 모든 주차 문서에 공통 로딩 화면을 연결했습니다. 내부 HTML 링크를 누르면 표시하고 목적지 페이지의 load 완료 후 숨깁니다. 같은 페이지 목차·외부 GitHub·새 탭·수정 키 클릭·다운로드는 가로채지 않습니다. 기본 링크 이동 자체를 취소하거나 늦추지 않습니다. 편집 중에는 이탈 확인을 유지하도록 로딩 표시를 건너뜁니다.

빠르게 로딩된 페이지에서도 확인할 수 있도록 도착 페이지에서 최소 280ms 표시하고 160ms로 사라집니다. 로딩이 완료되지 않아도 4초 후 표시를 해제합니다. OS ‘동작 줄이기’에서는 회전·페이드·최소 표시 시간을 생략합니다. JavaScript가 실행되지 않으면 기본 hidden 상태를 유지해 본문을 가리지 않습니다. 뒤로/앞으로 가기 캐시 복원 때 남은 표시를 해제합니다. 내려받는 HTML은 일시적인 로딩 상태를 제거한 뒤 저장합니다.

실제 브라우저 시각 검수는 아직 직접 수행하지 못했습니다. 페이지 이동 조건·로드 완료·실패 복구·캐시 복원과 다운로드 초기 상태는 모의 DOM 검사로 확인했습니다.

7. 실제 배포 URL에서 본인 GitHub 링크와 완료 주차별 실습을 모두 직접 누릅니다. 1280px와 모바일 화면을 다시 확인하고, REPORT의 배포 URL·Pass/Fail·완성도와 캡처를 최종 결과로 갱신합니다.

실명·생년월일·주소·이메일·전화번호·얼굴 사진·출신 학교명은 과제 페이지에 넣지 않습니다. 캡처에도 개인정보가 보이지 않도록 확인합니다. e-campus에는 최종 zip과 실제 배포 URL을 제출합니다.
