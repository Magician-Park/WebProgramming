01 / THE BIRTH OF THE WEB

네트워크에서 웹으로

강의자료 4~11쪽

인터넷이라는 이름은 네트워크 사이를 연결한다는 ‘inter-network’에서 출발한다. 웹은 인터넷 자체가 아니라 그 위에서 사용할 수 있는 정보 공유 방식 중 하나다.

  1. 1969

    ARPANET의 시작

    미국의 네 연구기관을 연결한 초기 네트워크가 만들어졌다. 오늘날 인터넷의 발전을 이해하는 출발점이다.

  2. 1982~83

    서로 다른 네트워크의 공통 규칙

    1982년 미국 국방부의 TCP/IP 표준 채택과 1983년 1월 1일 ARPANET의 TCP/IP 전환을 구분한다. 운영체제와 장비가 달라도 같은 통신 규칙으로 연결할 수 있게 됐다.

  3. 1986

    NSFNET과 학술 네트워크의 확대

    미국과학재단의 슈퍼컴퓨터들을 연결한 학술망이 구축됐다. 주요 지점을 잇는 백본과 대학·지역 네트워크의 연결로 인터넷 기반이 확대됐다.

  4. 1989

    팀 버너스리의 웹 제안

    CERN에서 일하던 팀 버너스리는 서로 다른 컴퓨터에 흩어진 연구 정보를 연결하고 공유하기 위해 하이퍼텍스트 기반의 시스템을 제안했다.

  5. 1990

    브라우저와 서버로 구현

    초기 웹 브라우저와 서버가 만들어졌다. 링크를 따라 문서 사이를 이동하는 아이디어가 실제로 작동하는 웹으로 이어졌다.

  6. 1993~94

    브라우저 보급과 웹의 대중화

    1993년 모자이크(Mosaic), 1994년 넷스케이프 내비게이터가 보급됐다. 그래픽 환경에서 문서와 이미지를 쉽게 탐색할 수 있게 되면서 웹의 사용이 확산됐다.

  7. 1994

    W3C와 웹 표준

    팀 버너스리를 중심으로 W3C가 설립됐다. 웹 기술을 공통된 규칙으로 발전시키고 다양한 환경에서 호환되도록 표준과 지침을 만든다.

웹의 탄생 확인: CERN · 초기 연표: W3C · TCP/IP 전환: Internet Society

왜 하이퍼텍스트인가?

하이퍼텍스트는 관련 문서나 데이터를 링크로 연결한다. 한 문서를 처음부터 끝까지 읽는 방식뿐 아니라, 필요한 정보를 찾아 다른 문서로 이동하는 탐색을 가능하게 한다.

강의자료의 2007년 인터넷 분포 지도와 2013년 이용자 지도는 웹의 규모와 지역 차이를 보여 주는 당시의 자료다. 현재 이용자 수나 보급률을 나타내는 통계로 읽지는 않는다.

02 / HTML & MARKUP

연결된 문서를 표현하는 언어

강의자료 12~15쪽

마크업은 인쇄 교정지에 문서의 구조와 표현을 표시하던 표식에서 유래했다. 마크업 언어는 태그를 사용해 내용에 의미와 구조를 더한다. HTML 문서는 일반 텍스트 파일로 저장하며 .html 또는 .htm 확장자를 사용한다.

문서 표준에서 웹 문서로 이어지는 흐름
시기기술이해할 점
1986SGML전자문서의 구조를 정의하는 국제 표준이다. 초기 HTML은 SGML을 바탕으로 정의됐다.
1990년대 초HTML웹에서 문서와 하이퍼링크를 표현하기 위한 비교적 간단한 마크업 언어로 등장했다.
1995HTML 2.0당시 HTML의 기능을 정리한 RFC 1866이 1995년 11월에 발표됐다.
1997HTML 4.0웹 문서의 구조와 표현을 발전시켰으며, CSS·JavaScript와 함께 더 다양한 페이지를 만들 수 있게 됐다.
1998XMLSGML을 간소화한 방식으로, 필요한 문서 형식을 정의해 데이터를 표현하고 교환한다.
2000XHTML 1.0HTML을 XML의 문법 규칙에 맞춰 표현한 문서 형식이다.
2004~07HTML5 개발2004년 WHATWG가 출범하고 2007년 W3C의 HTML 작업이 다시 추진됐다.
2014.10.28HTML5 권고안W3C가 HTML5를 권고안으로 발표했다. 의미 있는 문서 구조와 멀티미디어 등을 지원하는 웹의 기반이 됐다.

연도 확인: HTML 2.0 RFC · WHATWG 설립 설명 · W3C HTML5 발표

HTML · 구조

무엇이 제목이고 문단이며 링크인지 표현한다.

CSS · 표현

색상, 글꼴, 간격과 화면 배치를 정한다.

JavaScript · 동작

사용자 입력이나 클릭에 반응하는 기능을 만든다.

CSS와 JavaScript는 HTML에 포함된 하나의 언어가 아니라 각각 역할이 다른 기술이다. 함께 사용하면 구조·표현·동작을 나누어 관리할 수 있다.

서버

웹 자원을 제공하는 컴퓨터와 프로그램. 요청을 받아 문서·이미지 등의 응답을 보낸다.

강의자료의 서버 프로그램 예시는 Apache와 IIS, 클라이언트 프로그램 예시는 웹 브라우저다. 하드웨어뿐 아니라 그 역할을 수행하는 프로그램이 있어야 서비스를 이용할 수 있다.

기본 TCP/IP 웹 통신 모델에서의 역할 구분
기술주요 역할기억할 표현
IP주소를 바탕으로 패킷이 목적지 방향으로 전달되게 한다. IP 자체가 도착과 순서를 보장하지는 않는다.어디로 보낼까?

HTTP브라우저와 웹 서버가 자원을 요청하고 응답하는 서비스 규칙이다.무엇을 요청하고 어떻게 응답할까?

패킷은 데이터를 전달하는 작은 단위

네트워크에서는 데이터를 작은 단위로 나누어 전달한다. IP는 목적지 주소를 다루고, TCP는 데이터가 올바른 순서로 전달되는지를 관리한다. 프로토콜은 이 과정을 서로 이해하기 위한 규칙과 약속이다.

04 / IP, DNS & URL

주소를 찾고 자원의 위치를 지정하기

강의자료 18~21쪽

IPv4와 IPv6

IP 주소는 네트워크에서 통신 대상을 식별하는 숫자 기반 주소다. IPv4와 IPv6는 주소의 길이와 표기 방식이 다르다.

주소 길이와 표현의 차이
항목IPv4IPv6
길이32비트 · 4바이트128비트 · 16바이트
표기0~255 범위의 10진수 4개를 점으로 구분16진수 그룹을 콜론으로 구분, 0의 연속은 규칙에 따라 축약 가능
설명용 예시192.0.2.102001:db8::10
주소 공간2³²개 · 약 42억 9천만 개2¹²⁸개 · 훨씬 큰 주소 공간
핵심 배경연결되는 기기의 증가로 주소 공간의 한계가 드러남더 많은 기기를 연결할 수 있는 넓은 주소 공간 제공

규격 확인: IPv4 · RFC 791 · IPv6 · RFC 8200

도메인은 사람이 기억하는 이름, DNS는 주소 조회

도메인 이름은 숫자로 된 IP 주소보다 기억하기 쉬운 이름이다. DNS는 도메인 이름에 대응하는 IP 주소 등의 정보를 찾아 준다. 도메인과 IP가 항상 하나씩만 대응하는 것은 아니다.

  • www.daum.co.kr: www는 호스트 이름의 예, daum은 기관 이름의 예, co.kr은 국내 회사에서 사용하는 도메인 구조의 예다.
  • www.yahoo.com: 국가 코드 없이 .com을 사용하는 일반 도메인 구조의 예다.
  • 도메인 이름의 구성은 항상 세 단계나 네 단계로 고정되는 것은 아니다.

URL은 자원까지 가리키는 주소

URL(Uniform Resource Locator)은 인터넷 자원의 위치를 나타낸다. 도메인뿐 아니라 사용할 방식과 자원의 경로까지 함께 표현한다.

https://example.com/study/week01.html
└ https           사용할 방식(스킴)
└ example.com     도메인 이름
└ /study/         경로의 폴더 부분
└ week01.html     자원 이름의 예

위 주소와 IP 표의 주소는 구조를 설명하기 위한 예시다. URL의 경로가 항상 서버의 실제 폴더와 파일에 대응하는 것은 아니며, 서비스에 따라 요청을 처리하는 경로로 사용되기도 한다.

  1. 사용자가 URL을 입력한다.
  2. 필요한 경우 DNS로 도메인에 대응하는 IP 주소를 찾는다.
  3. 브라우저가 해당 서버에 자원을 요청한다.
  4. 서버의 응답을 받아 브라우저가 문서를 표시한다.

    05 / QUICK REVIEW

    개념을 내 말로 설명해 보기

    질문을 누르면 답을 확인할 수 있다.

    인터넷과 웹은 같은 것인가?

    인터넷은 연결 기반이고, 웹은 그 위에서 문서와 자원을 탐색하는 서비스다. 웹은 인터넷 서비스의 한 종류다.

    HTML, HTTP, URL은 각각 무엇을 담당하는가?

    HTML은 문서의 표현 구조, HTTP는 요청·응답 규칙, URL은 자원의 위치를 담당한다.

    IP만 있으면 데이터가 순서대로 도착하는가?

    IP 자체는 순서와 도착을 보장하지 않는다. 기본 TCP/IP 모델에서는 TCP가 순서와 재전송 등을 관리한다.

    IPv6의 주소 길이는 IPv4의 몇 배인가?

    IPv4는 32비트, IPv6는 128비트이므로 비트 길이는 4배다. 주소 개수는 4배가 아니라 2³²개에서 2¹²⁸개로 늘어난다.

    도메인 이름과 URL의 차이는 무엇인가?

    도메인은 서버를 찾을 때 사용하는 이름이며, URL은 스킴·도메인·경로 등을 포함해 자원의 위치를 더 구체적으로 나타낸다.
