WEEK 06 / TABLES

표: 행·열·제목과 셀 병합

Lec02 48~52·61쪽

table 안의 tr은 행, th는 제목 셀, td는 데이터 셀이다. caption은 표 제목이며 thead·tbody·tfoot으로 머리·본문·요약 행을 구분한다. th는 단순한 굵은 글씨가 아니라 데이터와 연결되는 제목의 의미를 갖는다.

표 구조와 병합
표현뜻확인할 점
rowspan="3"현재 셀이 아래 3개 행에 걸침뒤의 2개 행에는 이미 차지한 첫 셀을 다시 쓰지 않는다.
colspan="3"현재 셀이 가로 3개 열을 차지전체 열 수가 맞는지 센다.
scope="col" / "row"열 제목 / 행 제목데이터의 기준을 표시한다.
scope="rowgroup"행 묶음의 제목예제에서는 tbody의 3개 행에 걸친 과목 제목
caption / thead / tbody / tfoot제목 / 머리 / 데이터 / 요약구조만으로 본문에 스크롤이 생기지는 않는다.

EXAM FOCUS / BOX-MODEL

박스 모델: content → padding → border → margin

Lec05 2~5쪽 · 특히 3쪽 시험 강조

안쪽부터 내용(content), 내부 여백(padding), 테두리(border), 바깥 여백(margin) 순서다. padding은 내용과 테두리 사이, margin은 테두리 밖의 간격이다. 배경은 일반적으로 padding까지 칠해지며 margin에는 요소의 배경이 칠해지지 않는다.

각 영역의 역할
영역관련 속성구분
contentwidth, height글·이미지가 들어가는 영역
paddingpadding, padding-top 등테두리 안쪽; 음수 값은 사용할 수 없음
borderborder-width/style/colorpadding을 감싸는 경계
marginmargin, margin-left 등테두리 밖 간격; 일부 상황에서 음수도 가능

width가 무엇의 너비인지 먼저 확인

.box {
  box-sizing: content-box;
  width: 200px;
  height: 80px;
  padding: 20px;
  border: 2px solid #346248;
  margin: 20px;
}
  • content-box의 테두리까지 너비 = 200 + 20 × 2 + 2 × 2 = 244px.
  • 가로 margin까지 단순 합산한 범위 = 244 + 20 × 2 = 284px.
  • 테두리까지 높이 = 80 + 20 × 2 + 2 × 2 = 124px.
  • 같은 조건에서 border-box의 width를 200px로 지정하면 테두리까지 너비가 200px, 내용 너비는 156px다.

이 사이트의 공통 CSS는 border-box를 사용하므로 예제에서 content-box를 명시했다. margin은 border-box의 width에도 포함되지 않는다. 위 합산은 개별 박스의 가로 범위를 설명하며, 실제 세로 간격에는 블록 사이 margin 상쇄 등이 영향을 줄 수 있다.

여백 줄여쓰기

padding·margin의 값 순서
값 개수순서예
1개네 방향 동일padding: 10px
2개위·아래 / 왼쪽·오른쪽padding: 10px 20px
3개위 / 왼쪽·오른쪽 / 아래padding: 10px 20px 30px
4개위 → 오른쪽 → 아래 → 왼쪽padding: 10px 20px 30px 40px

border: 2px solid green은 두께·선 종류·색상이다. solid·dotted·dashed·double 등은 border-style 값이다. 테두리 색만 바꾼다고 기본 none인 선이 보이는 것은 아니다.

EXAM FOCUS / DISPLAY

display: 태그를 바꾸지 않고 배치 방식을 바꾸기

Lec05 6쪽 · 시험 강조

HTML 요소의 의미와 display 값은 별개다. p에 display: inline을 지정해도 문단 요소라는 의미는 유지되며, span에 display: block을 지정하면 블록처럼 배치된다.

display 값 비교
값배치와 크기주의
block일반 흐름에서 앞뒤로 줄을 나누며 width/height 지정 가능사용 가능한 너비를 채우는 auto 동작과 명시한 width를 구분
inline글 흐름 속에 배치; 일반적인 텍스트 inline에는 width/height 미적용padding·border가 그려져도 위아래 줄 간격을 같은 방식으로 늘리지는 않음
inline-block줄 안에 놓이지만 width/height 지정 가능사진·버튼처럼 크기가 있는 항목에 유용
table테이블 형식의 레이아웃 박스 생성CSS 배치 값만으로 HTML table의 의미가 생기지는 않음
list-item목록 항목 박스와 마커 생성li의 기본 배치와 관련
none요소와 자손의 박스가 생성되지 않음화면의 자리도 제거됨

테두리가 여러 조각으로 보이는 이유

inline 문단 안의 block 요소가 줄을 나누고, 긴 문장도 화면 너비에 맞춰 줄바꿈된다. 이때 같은 inline 문단의 배경과 테두리가 여러 조각으로 표시될 수 있다. 앞뒤 문단이 같은 줄에 이어지는 모습도 inline의 동작이다. 예제의 점선과 초록 테두리는 이 차이를 관찰하기 위한 표시다.

WEEK 06 / LAYOUT

위치·겹침·float·크기·넘침

Lec05 7~12쪽

position 네 가지
값기준과 공간좌표 적용
static일반 흐름의 위치top/right/bottom/left로 이동하지 않음
relative원래 위치를 기준으로 보이는 위치만 이동; 원래 자리 유지left: 20px이면 원래 위치보다 오른쪽
absolute일반 흐름에서 빠짐; containing block 기준보통 position: relative를 준 가까운 조상이 기준

.parent { position: relative; }
.badge { position: absolute; top: 10px; right: 10px; }
.shift { position: relative; left: 20px; }
.front { position: relative; z-index: 2; }

8쪽의 static 이미지에 top·left를 주어도 그 속성으로 이동하지 않는다. relative는 뒤 요소의 자리를 다시 배치하지 않으며, absolute는 보통 기준 조상을 명시한 뒤 사용한다. z-index는 같은 쌓임 맥락 안에서 앞뒤 순서를 조정한다. 다른 쌓임 맥락의 자손까지 무조건 큰 숫자가 앞서는 것은 아니다.

float와 clear

float: left/right는 콘텐츠를 한쪽에 두고 주변 텍스트가 감싸도록 만든다. clear: both는 앞선 양쪽 float를 피해 다음 블록을 배치한다. 10쪽에서 float만 있는 이미지의 top·left가 위치 지정 효과를 내는 것은 아니다.

.thumbnail { float: left; margin-right: 16px; }
.next-section { clear: both; }

크기 제한과 overflow

width·height는 크기를 지정하고 min/max-width·height는 제한을 둔다. 글이 늘어날 수 있는 영역에서는 고정 height보다 min-height와 자연스러운 높이를 먼저 검토한다.

overflow 값
값내용이 넘칠 때확인
visible박스 밖에도 보임다른 내용과 겹칠 수 있음
hidden영역 밖을 잘라 보이지 않게 함스크립트 등으로 스크롤되는 경우와 구분
scroll스크롤 영역으로 처리스크롤바 표현은 OS·브라우저 설정에도 영향받음
auto필요할 때 스크롤되도록 처리표·코드 영역에 유용
.notes { max-width: 100%; height: 140px; overflow: auto; }

둥근 모서리와 그림자

Lec05 13~14쪽

border-radius는 모서리를 둥글게 한다. 모서리별 속성을 쓸 수도 있다. box-shadow는 박스 주변 또는 안쪽에 그림자를 더하며, 그림자 자체가 박스의 레이아웃 크기를 늘리는 것은 아니다.

.card {
  border: 2px solid #346248;
  border-radius: 12px;
  box-shadow: 8px 8px 20px 2px rgba(52, 98, 72, 0.3);
}
.inset-card { box-shadow: 2px 2px 8px 1px #829489 inset; }

그림자의 첫 두 길이는 가로·세로 오프셋, 셋째는 흐림, 넷째는 확장 크기다. 색 뒤의 inset은 내부 그림자이며, 외부 그림자는 inset을 생략한다. 자료의 설명에 있는 ‘outset’을 box-shadow 값으로 넣지 않는다.

보완 근거: W3C · 배경·테두리·그림자

EXAM FOCUS / OPACITY

opacity: 투명해지는 것과 없어지는 것의 차이

Lec05 15쪽 · 시험 강조

opacity: 1은 불투명, 0은 완전히 투명, 0.5는 반투명이다. 값이 작을수록 뒤 배경이 더 비친다. 이 값은 요소를 렌더링한 결과 전체에 적용되어 글·테두리·자손도 함께 흐려진다.

.fade { opacity: 0.5; }
.only-background { background-color: rgba(52, 98, 72, 0.5); }
.hidden { visibility: hidden; }
.removed { display: none; }
보이지 않게 만드는 세 방법
방법자리 유지자손과 상호작용
opacity: 0유지완전히 투명해도 기본적으로 클릭·키보드 초점이 가능한 상태일 수 있음
visibility: hidden유지기본적으로 숨겨진 대상은 클릭·초점 대상에서 빠짐; 자손의 visibility 재지정은 별도
display: none제거요소와 자손의 박스·일반적인 초점 대상이 제거됨

시험에서 헷갈리기 쉬운 부분

opacity: 0은 공간 삭제가 아니다. 부모의 opacity: 0.5를 자식 opacity: 1로 되돌려 부모 합성의 영향을 없앨 수 없다. 배경만 반투명하게 하고 글은 선명하게 두려면 배경색의 알파 값을 사용한다.

visibility: collapse는 표의 행·열 같은 대상에서 특별한 동작을 하므로 일반 요소의 hidden과 무조건 같은 공간 처리라고 단정하지 않는다.

EXAM FOCUS / TRANSITION

transition: 상태 변경에 시간을 더하기

Lec05 16~17쪽 · 16쪽 시험 강조

16쪽의 :hover 코드는 색·글자·이미지 크기를 바꾸지만 transition 선언이 없어 즉시 바뀐다. 17쪽은 width 4s 같은 전환을 추가한다. transition은 시작 값과 끝 값 사이를 지정한 시간 동안 이어 주는 규칙이며, 스스로 값을 바꾸는 명령이 아니다.

/* HTML */
<button class="grow-logo" type="button">크기 바꾸기</button>

/* CSS: 초기 상태에 전환을 선언 */
.grow-logo {
  width: 120px;
  background-color: #e5eddd;
  transition: width 1s ease 0.2s, background-color 1s ease;
}
.grow-logo:hover, .grow-logo:focus-visible {
  width: 180px;
  background-color: #c5d7bd;
}
transition 줄여쓰기
부분위 예제의 값의미
propertywidth전환할 CSS 속성
duration1s변화를 완료하는 데 걸리는 시간
timing-functionease시간에 따른 진행 속도; 기본값 ease
delay0.2s상태가 바뀐 뒤 시작 전 기다리는 시간

첫 시간 값은 duration, 둘째는 delay다. 1s는 1000ms이고 duration 기본값 0s면 즉시 변경된다. 여러 속성은 쉼표로 나눈다. 기본 상태에 transition을 두면 상태에 들어갈 때와 빠져나올 때 모두 같은 전환 규칙을 유지하기 쉽다.

16쪽 원리: 즉시 변경

17쪽 원리: 1초 전환

width만 transition하면 height 등 다른 속성은 자동으로 같은 시간에 전환되지 않는다. 예를 들어 자료의 54×66 이미지에서 목표 108×132를 부드럽게 모두 바꾸려면 width와 height를 각각 지정한다. border-style 같은 이산적인 변화도 숫자 길이처럼 중간값이 생긴다고 생각하지 않는다.

img.logo {
  width: 54px;
  height: 66px;
  transition: width 4s, height 4s;
}
img.logo:hover { width: 108px; height: 132px; }

EXAM FOCUS / TRANSFORM

transform: 이동·크기·회전·기울임

Lec05 18쪽 · 시험 강조

transform은 요소를 배치한 뒤 보이는 좌표계를 변환한다. 일반 흐름에서 다른 요소가 차지하는 자리를 같은 방식으로 다시 배치하지 않으므로 주변과 겹칠 수 있다. 기본 회전·크기 변환 기준점은 일반적인 HTML 박스의 가운데다.

좌표변환 함수
함수예읽는 방법
translate(x, y)translate(30px, 30px)오른쪽 30px, 아래 30px 이동
scale(x, y)scale(3, 1.5)가로 3배, 세로 1.5배; scale(2)는 양쪽 2배
rotate(angle)rotate(45deg)회전 각도를 지정; 일반적인 좌→우 화면에서 양수는 시계 방향
skew(x-angle, y-angle)skew(30deg, 5deg)각 축 방향으로 기울임; 길이 단위가 아니라 각도
.move { transform: translate(30px, 30px); }
.scale { transform: scale(3, 1.5); }
.turn { transform: rotate(45deg); }
.skew { transform: skew(30deg, 5deg); }
.turn { transform-origin: 50% 50%; }

출력 비교의 scale은 공간이 좁아 1.5·1.2배로 줄여 표시했다. 원래 예제의 scale(3, 1.5)와 수치를 혼동하지 않는다. 18쪽의 translate 코드 30px과 설명 글 40px 차이는 30px로 통일해 정리했다.

여러 함수는 순서도 중요

/* 두 식은 일반적으로 다른 결과 */
.a { transform: translateX(80px) rotate(90deg); }
.b { transform: rotate(90deg) translateX(80px); }

변환 목록은 왼쪽부터 행렬을 곱해 구성하며, 점에 작용하는 최종 결과를 계산할 때는 오른쪽 함수부터 적용하는 것으로 생각할 수 있다. 위 A는 회전한 뒤 화면의 오른쪽으로 이동하고, B는 이동된 좌표까지 회전하므로 결과가 달라진다. 새 transform 선언은 기존 선언 뒤에 자동으로 누적되지 않으므로 함께 쓸 함수는 같은 값에 작성한다.

보완 근거: W3C · transform

EXAM FOCUS / ROTATE-EXAM

시험 연습: 이미지를 360도 rotate시키기

작성자가 전달한 예상 문제 · Lec05 16~18쪽 응용

‘360도 회전’이 최종 상태만 요구하는지, 돌아가는 과정까지 요구하는지 구분한다. transform: rotate(360deg)만 지정하면 0도와 최종 모양이 같아 한 바퀴 도는 과정이 보이지 않는다. 과정에는 시작·끝 값과 시간 규칙이 필요하다.

1. HTML: 이미지와 외부 CSS 연결

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>이미지 360도 회전</title>
  <link rel="stylesheet" href="rotation.css">
</head>
<body>
  <img class="spin" src="rotation-arrow.svg" width="120" height="120"
       alt="회전 연습용 화살표" tabindex="0">
</body>
</html>

2. CSS: 0도에서 360도로, 2초 동안

/* rotation.css */
.spin {
  display: block;
  width: 120px;
  height: 120px;
  transform: rotate(0deg);
  transform-origin: 50% 50%;
  transition: transform 2s linear;
}
.spin:hover, .spin:focus-visible {
  transform: rotate(360deg);
}
  1. 이미지의 시작 값을 rotate(0deg)로 둔다.
  2. transition의 대상은 rotate가 아니라 CSS 속성인 transform이다.
  3. 2s는 소요 시간, linear는 일정한 진행 속도다.
  4. hover 또는 키보드 초점 상태에서 목표를 rotate(360deg)로 바꾼다.
  5. 2초 동안 한 바퀴 회전하고 그 상태를 유지한다. 포인터·초점이 빠지면 0도로 돌아가는 전환이 일어난다.

3. 직접 확인: 체크하면 한 바퀴

아래는 같은 원리를 :checked로 실행한다. 체크를 켜면 0→360도, 끄면 360→0도로 바뀐다. 체크를 유지한다고 계속 반복하지 않는다. 전환이 끝난 뒤 다시 조작하면 전체 회전을 확인하기 쉽다.

Tab으로 체크박스에 이동한 뒤 Space로도 조작할 수 있습니다.

/* 위 체크박스 출력 예제의 핵심 */
.rotation6-stage img {
  transform: rotate(0deg);
  transition: transform 2s linear;
}
#rotation6-toggle:checked ~ .rotation6-stage img {
  transform: rotate(360deg);
}

답안에서 확인할 다섯 가지

img의 src 경로 · rotate(360deg)의 각도 단위 · 초기 0deg · transition: transform 2s · 값을 바꾸는 :hover 또는 :checked 상태를 확인한다. 원형처럼 대칭인 그림보다 방향이 있는 그림이 회전을 관찰하기 좋다.

반복 회전은 별도 요구

문제가 ‘계속 회전’을 요구할 때는 animation과 keyframes를 사용할 수 있다. 이는 이번 한 번의 전환 예제와 다른 동작이며 자료 범위 밖의 추가 응용이다.

@keyframes full-turn {
  from { transform: rotate(0deg); }
  to { transform: rotate(360deg); }
}
.loop { animation: full-turn 2s linear infinite; }

이 페이지는 OS의 ‘동작 줄이기’ 설정에서 전환을 생략하고 상태만 바꾼다. 해당 설정에서는 돌아가는 모션이 보이지 않는 것이 의도한 동작이다. 실제 출력 예제는 편집 저장으로 구조가 흐트러지지 않도록 고정했다.

    중간고사 대비 복습 질문

    정답을 열기 전에 코드와 예상 결과를 먼저 설명해 보세요.

    rowspan과 colspan의 방향은?

    rowspan은 아래 행으로, colspan은 옆 열로 합친다. 이미 병합 셀이 차지한 칸을 중복 작성하지 않는다.

    하위 ol은 ul 바로 아래에 두는가?

    해당 항목의 li 안에 넣어 관계를 표현한다.

    aside 태그만 쓰면 오른쪽에 배치되는가?

    부수 정보의 의미만 지정한다. 배치는 CSS가 결정한다.

    content-box에서 width 200px, padding 20px, border 2px이면?

    테두리까지 너비는 244px이며 좌우 margin 20px까지 합산한 가로 범위는 284px다.

    border-box의 width에 margin도 포함되는가?

    포함되지 않는다. width는 내용·padding·border를 포함한다.

    p를 inline으로 바꾸면 span의 HTML 의미도 바뀌는가?

    display는 박스 배치를 바꾸며 HTML 의미는 바꾸지 않는다.

    6쪽에서 strong에 display: none을 주면?

    강조 텍스트와 그 공간이 사라진다. br과 block으로 바꾼 span 때문에 전체가 한 줄인 것은 아니다.

    opacity: 0과 display: none은 같은가?

    opacity는 투명해도 자리가 유지되며 상호작용이 남을 수 있다. display: none은 박스와 자리를 제거한다.

    부모 opacity: 0.5를 자식 opacity: 1로 되돌릴 수 있는가?

    부모 전체의 합성 결과에 적용되므로 자식만으로 부모 합성의 영향을 취소할 수 없다.

    16쪽 hover 예제가 즉시 바뀌는 이유는?

    transition이 선언되지 않았기 때문이다. 17쪽에서 시간 규칙을 추가한다.

    transition: transform 2s linear에서 각 부분은?

    대상 속성 transform, 소요 시간 2초, 진행 속도 linear다.

    rotate(360deg)만 지정하면 한 바퀴 도는 과정이 보이는가?

    최종 방향만 같게 만든다. 과정에는 시작 값, 끝 값으로의 변경, 전환 시간이 필요하다.

    translate와 rotate의 순서를 바꾸면?

    일반적으로 결과가 다르다. 좌표계 변환의 합성 순서가 바뀐다.

    체크박스 예제를 켜 둔 채 기다리면 계속 회전하는가?

    한 번 목표 상태로 전환하고 멈춘다. 반복 회전은 animation 등의 별도 규칙이 필요하다.
