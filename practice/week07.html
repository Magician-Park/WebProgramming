WEEK 07 / FORM-BASICS

폼의 역할과 GET·POST의 차이

PDF 1~5쪽

폼은 입력을 하나로 묶고 처리 대상과 전송 방법을 정한다. 사용자가 값을 입력하고 전송하면 처리 프로그램이 요청을 읽고 결과를 반환한다. HTML은 입력 화면을 만들며, 저장·로그인·결제 같은 실제 처리는 별도의 프로그램이 담당한다.

<form action="/practice-request" method="get">
  <label for="topic">학습 주제</label>
  <input id="topic" name="topic" type="text" value="HTML">
  <button type="submit">확인</button>
</form>
form의 주요 속성
속성역할구분
action요청을 처리할 주소주소가 .js로 끝난다고 서버 처리 프로그램이 자동으로 생기지 않음
method="get"일반적으로 URL의 질의 문자열에 값 전달검색 등 조회에 적합; 주소·기록에 값이 노출될 수 있음
method="post"요청 본문에 값 전달POST 자체가 암호화가 아니며 서버·프록시 등에 크기 제한이 있을 수 있음
name폼 또는 컨트롤의 이름컨트롤의 name이 전송 데이터의 키로 쓰임

자료의 ‘POST는 양에 제한이 없다’는 설명은 구현 환경의 제한과 구분했다. 비밀번호를 password 필드에 입력하거나 POST로 보낸다고 전송이 암호화되는 것은 아니다. 실제 서비스에는 HTTPS와 서버 측 검증이 필요하다.

WEEK 07 / LIBRARY-CAMPUS

서울·천안 캠퍼스와 도서 구입 희망 신청

추가 실습 · 제공한 doc06.html과 웹 참고 페이지의 입력 폼

상명대학교 도서관에 구입 희망 도서를 신청하는 상황에 연결해 radio·checkbox·select·textarea를 함께 사용해 본다. 캠퍼스는 하나만 선택하고, 희망 분야는 여러 개를 선택한다. 선택은 입력값을 정하는 과정이며 실제 신청 접수나 도서관 페이지 이동은 이 실험에서 실행하지 않는다.

웹 참고: 다양한 입력 폼 실습 페이지 · 추가 참고: 작성자가 제공한 doc06.html

원본을 읽고 확인한 값과 보완한 구조
관찰 항목원본에서 확인한 내용이 페이지에서 실험할 내용
캠퍼스 코드웹 참고는 00=서울·01=천안이다. 첨부 doc06은 00 옆에 천안, 01 옆에 서울을 적었으나 글자가 input 시작 태그 안에 들어 있다.첨부 파일의 작성 의도에 맞춰 00=천안·01=서울로 재구성했다. 숫자 자체가 캠퍼스를 뜻하는 것은 아니며 서비스가 정하는 약속이다.
기본 선택두 자료 모두 천안에 해당하는 항목에 checked를 작성했다. 값은 자료별로 다르다.이 예제의 기본값은 천안(00)이며 초기화하면 다시 천안이 선택된다.
그룹과 이름캠퍼스 radio는 같은 name=campuscode, 분야 checkbox는 같은 name=books를 쓴다. doc06의 성명과 암호는 name=person이 중복된다.하나의 캠퍼스 값과 여러 books 값을 비교한다. 성명 대신 연습용 활동명을 쓰고 암호는 기존 암호 실험에서 따로 다룬다.
라벨과 선택 목록doc06의 캠퍼스 글자가 태그 안에 있고 password 입력이 select 내부에 섞여 있다. 웹 참고에는 textarea 및 일반 버튼의 표기 오류도 있다.캠퍼스·분야는 label로 감싸고 select에는 option만 넣는다. textarea는 정상 종료 태그, 버튼은 올바른 type과 외부 스크립트로 작성한다.
전송과 초기화method=get, action=form_app.js, 신청·취소·일반 버튼이 있다.GET 요청 모양만 미리 본다. reset은 뒤로 가거나 신청을 취소하는 대신 최초 입력값·checked·selected로 되돌린다.

같은 name으로 하나 선택, 여러 value로 복수 선택

campuscode라는 같은 이름의 radio는 하나만 선택된다. 표시 글자와 서버에 전달될 value는 별개다. books는 선택한 개수만큼 같은 이름의 값이 반복되고 선택하지 않은 checkbox는 전송 데이터에 포함되지 않는다. 다른 이름의 radio는 별도 그룹이다.

<fieldset>
  <legend>도서관 캠퍼스 선택</legend>
  <label><input type="radio" name="campuscode" value="00" checked>천안</label>
  <label><input type="radio" name="campuscode" value="01">서울</label>
</fieldset>
<label><input type="checkbox" name="books" value="computer">컴퓨터</label>
<label><input type="checkbox" name="books" value="economy">경제</label>
<label><input type="checkbox" name="books" value="common">상식</label>

추가 실험 · 도서관 캠퍼스 선택 폼

연습용 값을 사용하세요. 캠퍼스와 분야를 바꿔 보고 요청 모양을 확인합니다. 입력은 서버로 전송하거나 저장하지 않습니다.

도서관 캠퍼스 · 하나만 선택
현재 선택: 천안 · campuscode=00
구입 희망 분야 · 복수 선택 가능
캠퍼스·분야를 선택한 뒤 신청값 미리보기를 누르세요.

이렇게 바꿔 보세요

  1. 서울을 선택하고 현재 선택이 campuscode=01로 바뀌는지 확인한다.
  2. 컴퓨터와 경제를 함께 선택하고 요청에 books=computer와 books=economy가 반복되는지 확인한다.
  3. 직업을 바꾸고 비고를 입력한 뒤 name/value 목록과 URL 인코딩된 GET 쿼리를 비교한다.
  4. 분야를 모두 해제하면 books 항목이 사라지는지 확인한다.
  5. 처음 선택으로를 누르면 천안·학생·분야 미선택·빈 비고로 되돌아가는지 확인한다.

HTML은 라벨·단일/복수 선택·이메일 형식 검사와 초기화를 담당한다. 현재 선택 출력과 FormData·URLSearchParams로 만든 요청 미리보기는 JavaScript가 담당한다. 원본의 action 주소만으로 신청 처리 프로그램이 완성되는 것은 아니다.

서울·천안을 선택하면 실제 도서관으로 이동하는가?

이 실습의 radio는 campuscode 입력값만 바꾼다. 실제 도서관 주소로 이동하려면 별도 링크나 이동 동작을 작성해야 한다. 원본 폼은 선택값을 신청 대상 주소로 보내는 구조다.

천안을 선택했는데 왜 어떤 자료는 01이고 이 예제는 00인가?

제공된 두 자료의 코드 대응이 다르기 때문이다. 이 페이지는 첨부 doc06의 작성 의도를 따라 천안을 00으로 정했다. 처리 프로그램과의 약속이 중요하며 브라우저가 숫자로 캠퍼스를 판단하지 않는다.

WEEK 07 / VALIDATION

서식 입력과 유효성 검사

PDF 15~17쪽

email·url·tel·search는 목적에 맞는 입력 컨트롤이다. email과 url은 입력 형식을 검사하지만 실제 계정이나 사이트가 존재하는지 확인하지 않는다. tel은 형식이 국가마다 다르므로 타입만으로 특정 전화번호 규칙을 강제하지 않으며 pattern으로 원하는 규칙을 더할 수 있다.

입력 검사와 안내 속성
속성역할구분
required지원하는 컨트롤의 값·선택을 필수로 함선택 항목의 빈 문자열과 구분
pattern지원하는 텍스트 타입의 값에 정규식 규칙 적용숫자 범위에는 number의 min/max/step 사용
minlength / maxlength문자 길이 제한number의 숫자 자릿수 제한으로 사용하지 않음
placeholder입력 예시를 흐리게 표시초기값·label·검사 규칙을 대신하지 않음
autocomplete자동 입력의 힌트항상 저장·자동입력 동작을 완전히 차단한다는 뜻은 아님
autofocus페이지에서 초점을 자동 지정이 페이지에서는 읽기 흐름을 위해 사용하지 않음
novalidate제출 시 기본 제약 검사를 생략서버 검증을 대신하거나 보안을 제공하지 않음
<input type="text" pattern="[A-Za-z]{2}[0-9]{2}" required>
<input type="number" min="0" max="100" step="10" value="20">
<input type="email" required>
<input type="tel" pattern="[0-9]{2,3}-[0-9]{3,4}-[0-9]{4}">

실험 2 · 일부러 틀린 값을 넣어 보기

빈 필수 값, AB12 대신 1234, 이메일 대신 abc, 점수 25 등을 입력하고 검사해 보세요.

입력 후 검사 버튼을 눌러 보세요. 실제 연락처 대신 연습값을 사용하세요.

email에 multiple을 지정하면 쉼표로 구분한 여러 주소를 받을 수 있다. URL 입력은 반드시 http만 허용하는 장치가 아니라 URL 구문을 검사하는 입력이다. 서비스에서 특정 프로토콜만 받으려면 별도 정책을 적용한다.

기본 검사는 HTML 속성과 브라우저가 수행한다. 입력 검사 통과 결과를 화면에 표시하는 부분은 JavaScript다. 클라이언트 검사는 수정하거나 우회할 수 있어 실제 서비스의 서버 검사를 대체하지 않는다. 오류 안내의 모양과 문구는 브라우저·언어에 따라 다르다.

time10:30시간; step의 단위는 초
datetime-local2026-10-17T10:30시간대 정보 없는 지역 날짜와 시간
datetime현재 사용하지 않음자료에 나오지만 폐기된 타입

week의 W01은 단순히 1월 1일부터 시작하는 구간이 아니다. ISO 주 규칙을 사용하므로 연말 날짜가 다음 주 기준 연도에 들어갈 수도 있다. datetime-local에는 시간대가 포함되지 않으며 자동으로 UTC로 변환되지 않는다.

<input type="date" min="2026-10-01" max="2026-12-31">
<input type="time" min="09:00" max="18:00" step="900">
<input type="datetime-local" value="2026-10-17T10:00">

실험 3 · 날짜와 시간 고르기

2026년 10~12월의 연습 날짜, 09:00~18:00 사이 시간을 선택합니다. 종료 시간을 시작 시간보다 이르게 바꿔 보세요.

실제 예약이 아닌 날짜·시간 형식 실험입니다.

min/max는 각 입력의 범위를 검사한다. ‘종료가 시작보다 늦어야 한다’는 두 필드 사이 관계는 이 예제에서 JavaScript의 setCustomValidity로 보완했다. 날짜 선택기의 모양과 month/week의 전용 UI 지원은 브라우저마다 다르다. 화면의 날짜 표시는 지역화되어도 제출 값의 형식은 정해져 있다.

추천 도서를 선택하거나 직접 입력하세요. 추천 도서로 확정하면 예제 가격을 채웁니다. 가격·권수·선호도를 바꾸면서 결과를 확인하세요.

실제 도서 가격·구매 서비스가 아닌 강의 예제의 금액입니다.

원래 도서 구입 요청 예제에 JavaScript 계산과 output을 연결했다. 추천 도서 가격 연동도 JavaScript로 추가한 기능이며 datalist만의 자동 동작이 아니다. color 선택은 네이티브 UI와 코드 출력으로 관찰하므로 인라인 style을 만들지 않는다.

datalist 후보가 나타나는 방식은 브라우저에 따라 다르다. 후보 목록이 키보드나 보조 기술에서 불편한 상황에는 다른 선택 방식도 고려한다.

WEEK 07 / FILE-PASSWORD

password·file·hidden의 한계 이해

PDF 6~7·12쪽 복습

password는 화면에서 입력 문자를 가려 주는 컨트롤이다. 표시를 가렸다고 암호화·인증이 이루어지지 않는다. file은 사용자가 파일을 선택하는 입력이며 선택만으로 서버 업로드가 되는 것은 아니다. accept는 선택할 종류의 힌트로, 실제 서비스의 서버 파일 검증을 대신하지 않는다.

실험 5 · 암호 표시와 파일 선택

문자를 입력하고 표시 방식을 바꿔 보세요.

선택한 파일이 없습니다.

파일 실험은 이름과 크기만 표시하고 파일 내용을 읽거나 전송하지 않는다. 입력한 암호와 파일 정보는 저장하지 않는다. hidden은 화면에서만 숨겨진 필드이며 개발 도구로 볼 수 있고 사용자 측에서 바꿀 수 있다.

    WEEK 07 / REVIEW

    개념 설명으로 마무리하기

    핵심 차이 복습

    id와 name은 같은 역할인가?

    id는 label·DOM·문서 안의 대상을 연결하고 name은 전송 이름으로 쓰인다.

    placeholder는 입력값인가?

    값이 비어 있을 때 보이는 안내이며 초기 value나 label을 대신하지 않는다.

    POST면 값이 자동으로 암호화되는가?

    POST는 본문 전달 방식이다. 전송 보호에는 HTTPS 등이 필요하다.

    reset을 누르면 모든 칸이 비어야 하는가?

    처음의 값과 체크·선택 상태로 돌아가는 동작이다.

    HTML 속성만으로 가격×권수가 자동 계산되는가?

    output은 표시 요소다. 이 실험은 JavaScript로 계산한다.

    현재 사용하지 않는 강의자료 속 요소는?

    keygen과 input type=datetime은 현재 표준 예제로 사용하지 않는다.
