01 / FROM THE WEB TO HTML5

1주차 복습에서 HTML5로

강의자료 2~13쪽

인터넷은 서로 다른 네트워크의 연결 기반이다. 웹은 그 위에서 하이퍼링크로 문서와 자원을 탐색하는 서비스이며, HTML·HTTP·URL은 각각 문서 구조·요청과 응답·자원의 위치를 담당한다.

  1. 1969년 ARPANET에서 시작해 TCP/IP와 NSFNET을 통해 네트워크 연결이 확대됐다.
  2. 1989년 CERN의 팀 버너스리가 정보 공유를 위해 웹을 제안했다.
  3. 모자이크와 넷스케이프 같은 브라우저의 보급으로 웹의 사용이 확산됐다.
  4. 1994년 W3C가 출범해 공통된 웹 기술과 표준의 발전을 추진했다.

마크업은 문서에 의미와 구조를 더하는 표식이다. 초기 HTML은 SGML을 바탕으로 정의됐고, XML·XHTML을 거쳐 HTML5 개발로 이어졌다. HTML 2.0은 1995년, WHATWG 설립은 2004년으로 정리한다.

관련 내용: 1주차 웹의 역사 · HTML 발전 연표와 연도 근거

역사 자료를 읽는 기준

1982년 TCP/IP 표준 채택과 1983년 ARPANET의 실제 전환을 구분한다. 초기 ARPANET이 처음부터 IP를 사용했다고 이해하지 않는다. 자료의 2007·2013년 지도와 당시 W3C 조직 정보는 그 시점의 자료다.

02 / HTML5 & THE WEB PLATFORM

문서에서 웹 애플리케이션으로

강의자료 14~18쪽

HTML5의 방향은 의미 있는 구조, 더 편리한 입력, 멀티미디어와 웹 애플리케이션 지원이다. HTML은 구조, CSS는 표현, JavaScript는 동작을 맡는다.

강의자료에서 소개한 네 가지 변화
영역주요 내용이해할 점
의미 있는 구조header, nav, section, article, aside, footer문서의 영역과 역할을 표현한다. 단순한 색상·배치와는 구분한다.
입력과 미디어date·number·color·file 입력, video·audio·canvas, SVG·MathML표준 요소와 기능으로 다양한 입력과 미디어를 다룬다.
CSS의 발전모서리·그림자·다단·변환·전환·애니메이션HTML 문서에 연결한 스타일시트가 표현을 담당한다. 기능별 브라우저 지원을 확인한다.
API와 모바일저장·파일·위치정보·백그라운드 작업·통신 등의 APIJavaScript로 기능을 사용하며, 여러 API는 별도의 웹 표준으로 정의된다.

API는 프로그램이 특정 기능을 사용하기 위한 인터페이스다. 위치정보·저장·오프라인 기능 등이 모바일 환경에 도움이 되지만, 지원 여부와 사용 조건은 기능마다 다르다. 이 페이지는 개념을 설명하며 위치정보나 파일 접근을 자동 요청하지 않는다.

‘HTML5’와 모든 웹 기술을 동일시하지 않기

자료에서 HTML5라는 이름으로 함께 소개한 기능도 실제로는 HTML·CSS·JavaScript와 개별 API 표준이 협력하는 구조다. 자료의 Application Cache는 역사적 기술이며 새 예제에 사용하지 않는다.

03 / NETWORK BASICS

요청이 서버까지 전달되는 과정

강의자료 19~24쪽

클라이언트인 브라우저가 자원을 요청하면 서버가 응답한다. 서버에는 Apache·IIS 같은 서비스 프로그램이 필요하고, 브라우저는 응답받은 문서를 화면에 표현한다.

비슷해 보이는 용어의 역할 구분
용어역할기억할 점
TCP순서·흐름·재전송 등을 관리해 신뢰성 있는 데이터 전달을 제공전달이 제대로 이뤄졌는가?
IP주소를 바탕으로 패킷을 목적지 방향으로 전달IP 자체는 도착과 순서를 보장하지 않는다.
HTTP웹 자원의 요청·응답 규칙문서 구조 언어인 HTML과 다르다.
DNS도메인에 대응하는 IP 주소 등의 정보 조회도메인과 IP가 항상 하나씩 대응하지는 않는다.
URL자원의 위치를 표현스킴·도메인·경로 등을 포함한다.

IPv4는 32비트(4바이트), IPv6는 128비트(16바이트)다. 주소 공간은 각각 2³²개와 2¹²⁸개이므로 비트 길이와 가능한 주소 개수의 증가를 구분한다.

https://example.com/learn/week02.html
https          사용할 방식(스킴)
example.com    도메인 이름
/learn/week02.html    자원의 경로

위 주소는 설명용이다. URL 경로가 항상 실제 폴더나 파일을 뜻하지는 않는다. 도메인의 단계 수 역시 모든 이름에서 동일하게 고정되지 않는다.

1주차 IP·DNS·URL 비교표에서 자세한 내용을 확인할 수 있다.

04 / WEB BROWSERS

같은 문서를 여러 환경에서 읽기

강의자료 25~29쪽

브라우저는 문서 표시뿐 아니라 링크 이동, 탭, 즐겨찾기, 저장·인쇄, 소스 보기와 보안 관리 등을 제공하는 클라이언트 프로그램이다. 같은 웹 문서라도 브라우저와 버전에 따라 지원 기능과 화면이 다를 수 있다.

  • 넷스케이프와 Internet Explorer: 초기 상용 브라우저 보급과 경쟁의 흐름을 이해하는 사례다.
  • Chrome, Firefox, Safari, Opera: 강의자료에 소개된 다양한 브라우저의 사례다.
  • 자료의 점유율 그래프와 ‘선두’ 등의 표현은 당시 설명이며 현재 순위나 추천 기준으로 사용하지 않는다.
  • 문서는 표준에 맞춰 작성하고, 실제 이용할 브라우저와 화면 크기에서 확인한다.

05 / DOCUMENT STRUCTURE

기본 HTML 문서 만들기

강의자료 30~32·35~36쪽

문서 형식 선언 다음에 루트 요소인 html을 두고, 그 안을 head와 body로 구분한다. head에는 문서 정보와 외부 자원의 연결을, body에는 사용자가 읽고 사용하는 콘텐츠를 작성한다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="description" content="HTML 기본 문서 학습 기록">
  <title>2주차 학습 기록</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <main>
    <h1>HTML 기본 문서</h1>
    <p>문서의 구조를 작성합니다.</p>
  </main>
</body>
</html>
코드에서 확인할 항목
항목역할
DOCTYPE문서가 표준 HTML 문서임을 선언한다. HTML 요소나 화면에 보이는 제목이 아니다.
html lang="ko"문서의 기본 언어가 한국어임을 지정한다.
head / title문서의 메타정보와 브라우저 탭 등에 쓰이는 제목을 정한다.
meta charsetUTF-8 같은 문자 인코딩을 지정한다.
meta name / contentdescription·author·keywords 등의 종류와 값을 지정한다.
body제목·문단·링크 등 문서의 콘텐츠를 작성한다.

메타데이터 이름을 정확하게 쓰기

자료의 meta authors나 meta keyword 같은 예제를 그대로 사용하지 않는다. 저자는 name="author", 키워드는 name="keywords"와 content를 사용한다. 문서 인코딩은 meta charset="UTF-8"로 지정한다.

06 / ELEMENTS & ATTRIBUTES

요소·태그·속성의 차이

강의자료 33~34쪽

<a href="../index.html#weekly" class="study-link">학습 기록</a>
│                  │                                  │
시작 태그         속성                              내용 + 종료 태그
  • 요소는 시작 태그·내용·종료 태그 등으로 표현하는 문서 구성 단위다.
  • 속성은 시작 태그 안에 추가하며 여러 속성은 공백으로 구분한다. 값에는 보통 따옴표를 사용한다.
  • HTML 태그 이름은 대소문자를 구분하지 않지만 일관된 소문자로 작성하면 읽기 쉽다.
  • br·hr·img 같은 빈 요소는 종료 태그를 쓰지 않는다. HTML에서 마지막 /는 필수가 아니다.
  • 요소는 허용된 자식 구조에 맞춰 중첩한다. 태그가 교차해 닫히거나 p 안에 h2를 넣는 구조는 피한다.

문단 안의 강조

<p>이 문장은 <strong>중요합니다</strong>.</p>

제목과 문단은 나란히

<h2>문서 제목</h2>
<p>제목 아래의 설명입니다.</p>

링크의 href는 이동할 주소다. 새 창이나 탭에 여는 예약된 target 값은 _blank이며, 이름이 blank인 창을 지정하는 값과 구분한다. 표의 테두리 같은 외형은 border 속성 대신 외부 CSS로 작성한다.

문법 확인: WHATWG 요소와 빈 요소

07 / CHARACTERS & COMMENTS

태그처럼 보이는 문자를 글자로 표시하기

강의자료 37쪽

HTML에서 특별한 의미로 사용되는 문자나 키보드로 쓰기 어려운 문자는 문자 참조로 표시할 수 있다. 공백과 들여쓰기 배치는 CSS로 관리하고, 줄바꿈하지 않는 공백은 필요한 경우에만 사용한다.

08 / TEXT & MEANING

문단과 텍스트를 의미에 맞게 선택하기

강의자료 38~44쪽

모양보다 먼저 생각할 역할
요소의미와 사용기억할 점
h1~h6제목의 계층크기를 고르는 대신 문서의 제목 순서를 표현한다.
p / br문단 / 문단 안의 줄바꿈새 문단은 p, 같은 문단의 필요한 줄바꿈은 br.
hr주제나 내용의 전환단순한 장식 선은 CSS로 표현할 수 있다.
pre공백과 줄바꿈 형식 유지코드 예시는 pre와 code를 함께 사용할 수 있다.
blockquote다른 출처에서 인용한 블록들여쓰기만 만들기 위한 요소가 아니다.
em / strong강세 강조 / 중요성기울임·굵기라는 모양과 의미를 구분한다.
small부연 설명이나 작은 글씨로 쓰이는 주석성 내용글자 크기만 줄일 때는 CSS를 사용한다.
mark현재 문맥에서 관련된 부분 표시검색 결과나 학습 중 주목하는 부분에 사용할 수 있다.
sub / sup아래첨자 / 위첨자화학식·수식처럼 해당 표기가 필요한 내용에 사용한다.

코드 예시

<h3>텍스트의 의미</h3>
<p><em>강조</em>와 <strong>중요성</strong>을 구분합니다.</p>
<p><mark>복습할 부분</mark></p>
<p><small>학습용 예시입니다.</small></p>
<p>물: H<sub>2</sub>O, 제곱: x<sup>2</sup></p>

    핵심 내용을 확인하기

    질문을 누르면 답을 확인할 수 있다.

    head의 title과 body의 h1은 무엇이 다른가?

    title은 문서 제목으로 브라우저 탭 등에 사용되고, h1은 화면에 표시되는 문서의 주요 제목이다.

    요소와 속성은 어떻게 구분하는가?

    요소는 문서를 구성하는 단위다. 속성은 시작 태그 안에 적는 이름과 값으로, 링크 주소나 언어 같은 추가 정보를 지정한다.

    br과 p 중 무엇으로 새 문단을 만드는가?

    새 문단은 p로 만든다. br은 문단 안에서 줄만 바꿀 때 사용한다.

    <h1>이라는 글자를 화면에 표시하려면?

    소스에 &lt;h1&gt;를 적으면 태그로 해석되지 않고 <h1>이라는 문자로 표시된다.

    small은 단순히 글자 크기를 줄이는 요소인가?

    부연 설명 같은 의미를 가진 요소다. 의미와 관계없이 크기만 조절하려면 CSS를 사용한다.

    HTML5 문서면 모든 기능이 모든 브라우저에서 같은가?

    요소·CSS·API의 지원은 브라우저와 버전에 따라 다르다. 표준 문법 검사와 실제 환경의 동작 확인을 함께 진행한다.
