상대 주소는 현재 문서의 위치를 기준으로 해석한다. 문서를 다른 폴더로 옮기면 같은 상대 주소가 다른 파일을 가리킬 수 있다. 단순히 href를 빈 값으로 두는 대신 목적지 경로를 분명히 작성한다.

<!-- 링크의 시작점 -->
<a href="#book001">첫 번째 참고도서 소개</a>

<!-- 도착점: id에는 #을 붙이지 않는다 -->
<section id="book001">
  <h3>첫 번째 참고도서</h3>
  <p>도서의 설명을 작성합니다.</p>
</section>

자료에서는 a id="book001" 같은 빈 앵커로 도착점을 지정한다. 목적지를 a에만 설정할 필요는 없으며 section·제목·span·img 같은 요소에 고유한 id를 지정할 수도 있다. 이것이 뉴스의 span id="up"과 웹툰의 img id="up"으로 이어진다.

예제 코드는 유효한 구조로 쓰기

자료의 스마트 따옴표는 코드용 따옴표로 바꾸고, br은 종료 태그 없이 쓴다. ol 안의 항목은 li로 감싸며, 표의 테두리와 위치 같은 표현은 외부 CSS로 분리한다.

이미지 형식의 특징과 압축 비교를 읽는 기준
형식특징자료에서 이해할 점
GIF팔레트 기반으로 제한된 색상을 표현일반적으로 최대 256색 팔레트를 사용하며 단순한 그림과 색이 적은 이미지에 활용된다.
JPEG사진처럼 색상 변화가 많은 이미지에 활용보통 손실 압축을 사용하며 품질 설정과 파일 크기를 함께 살펴본다.
PNG무손실 압축과 투명도 지원도형·문자·투명 배경 이미지에 활용된다. 비압축 형식이라고 이해하지 않는다.

자료 14쪽의 압축률은 두 예제 이미지의 비교 결과다. GIF가 언제나 가장 작거나 PNG가 항상 더 크다고 일반화하지 않는다. 실제 크기는 이미지의 내용·해상도·색상·압축 설정에 따라 달라진다.

<img src="anchor-panel.svg"

     alt="문서 내 이동 실습을 설명하는 그림">
이미지를 표시할 때 확인할 속성
속성역할
src이미지의 파일 이름 또는 경로를 지정한다. 상대 경로라면 현재 문서를 기준으로 찾는다.
width / height이미지의 표시 크기와 비율을 지정한다. 반응형 화면에서는 CSS와 함께 조정한다.
alt이미지 대신 전달할 내용을 설명한다. 로드 실패와 비시각적 이용을 함께 고려한다.

클릭하는 이미지의 alt는 이동 기능이나 목적지를 이해할 수 있게 작성한다. 이미지의 정렬은 오래된 align 속성보다 CSS로 표현하며, 너비와 높이를 임의로 바꿔 비율이 찌그러지지 않게 한다.

figure와 figcaption, 이미지 링크

figure는 그림·사진·다이어그램 등 독립적으로 설명할 콘텐츠를 묶고, figcaption은 그 콘텐츠의 설명을 같은 figure 안에 작성한다. 이미지를 a로 감싸면 그림 전체가 링크의 클릭 영역이 된다.

<figure>
  <a href="#webtoon-case">
    <img src="anchor-panel.svg" width="320" height="160"
         alt="웹툰 이미지 링크 실습으로 이동">
  </a>
  <figcaption>이미지를 누르면 웹툰 실습으로 이동합니다.</figcaption>
</figure>

자료 19쪽의 figcation은 figcaption으로 고쳐 작성한다. 이 예제에서는 설명을 a 밖의 figure 자식으로 두어 그림·링크·설명의 구조를 분명히 했다. 실제 책 표지나 웹툰 장면을 복제하지 않고 기존 학습용 그림을 사용했다.

3주차에는 저장한 네이버 뉴스 기사와 웹툰 페이지의 HTML을 열어 문서 내 위치 이동을 실습했다. 본문이나 아래쪽 이미지를 클릭하면 상단에 지정한 위치로 올라가도록 링크와 도착점을 연결했다.

첨부 ZIP의 실제 저장 HTML에서 확인한 내용
대상도착점클릭할 링크소스 확인

02 / FRAGMENT LINKS

링크와 도착점의 이름을 맞추기

도착점

<span id="up">기사 제목</span>

id는 이동할 요소의 식별자다. id 값에는 #을 붙이지 않는다.

이동할 링크

<a href="#up">위로 이동</a>

href의 # 뒤에 도착점의 id를 적는다. up이라는 이름이 서로 같아야 한다.

  1. 사용자가 링크를 클릭한다.
  2. 브라우저가 href의 #up을 문서 내 위치를 가리키는 프래그먼트로 읽는다.
  3. 현재 문서에서 id="up"인 요소를 찾는다.
  4. 해당 요소가 보이도록 문서의 위치를 이동한다.

이름이 up이라서 올라가는 것은 아니다

up은 개발자가 정한 이름이다. 요소가 위쪽에 있으면 위로 이동하고, 아래쪽에 있으면 아래로 이동한다. up 대신 summary나 chapter-1을 써도 링크와 id가 일치하면 같은 원리로 동작한다.

id="up"은 반드시 페이지의 스크롤 위치 0을 뜻하지 않는다. 뉴스 실습에서는 기사 제목, 웹툰 실습에서는 상단 안내 이미지가 도착점이다. 이름이 없는 링크나 도착점이 없는 링크는 의도한 위치로 이동할 수 없다.

<img src="상단안내이미지.jpg" alt="연령 안내" id="up">

<!-- 아래쪽 이미지 클릭 → 상단 이미지로 이동 -->
<a href="#up">
  <img src="마지막이미지.jpg" alt="위로 이동할 웹툰 이미지">
</a>

이미지 경로와 alt 문구는 설명하기 쉽게 바꿨다. 저장본에서는 마지막 이미지의 id가 content_image_80이었다. 실제 실습의 이동 목표는 상단의 id="up"인 이미지다.

05 / TOP BUTTON IMPLEMENTATIONS

직접 만든 앵커와 원래 TOP 버튼 비교

저장한 페이지에는 직접 추가한 #up 링크와 별도로 원래의 ‘맨위로’ 컨트롤도 남아 있다. 두 종류의 코드를 구분해 확인했다.

제공한 파일에서 확인한 이동 방식
구분확인한 코드이동 기준
실습에서 추가한 링크a href="#up"과 id="up"이름으로 지정한 요소의 위치
뉴스의 원래 맨위로goTop / _MOVE_TOP 클릭 → moveTop() → window.scrollTo(0, 0)페이지 좌표의 맨 위
웹툰의 원래 맨위로.up_down_area .link_top 클릭 → window.scrollTo(0, 0)페이지 좌표의 맨 위
 
// 저장된 뉴스·웹툰 스크립트에서 확인한 핵심 동작
window.scrollTo(0, 0);

// 직접 추가한 HTML 앵커 링크는 id가 있는 요소로 이동
// <a href="#up">위로 이동</a>

뉴스의 read.min.js는 _MOVE_TOP 클릭에서 기본 링크 동작을 막고 moveTop()을 호출한다. 그 함수 안에서 window.scrollTo(0, 0)이 실행된다. 웹툰의 detail-scrolltoon 스크립트도 맨위로 버튼의 클릭 이벤트에서 같은 좌표 이동을 호출한다. HTML의 버튼 모양이나 onclick의 문자열만 보고 동작 전체를 판단하지 않고 연결된 스크립트까지 확인했다.

부드러운 이동은 별도 설정

이 학습 페이지에는 외부 CSS의 scroll-behavior: smooth가 적용되어 앵커 이동이 부드럽게 보인다. 이는 #up의 의미 자체와는 별개다. 동작 줄이기를 요청한 환경에서는 기존 설정대로 즉시 이동한다.

html { scroll-behavior: smooth; }
@media (prefers-reduced-motion: reduce) {
  html { scroll-behavior: auto; }
}

이력서의 맨 위 영역과 주차별 기록으로 이동하는 링크도 프래그먼트 주소를 사용한다.

06 / WHAT I PRACTISED

실습 순서와 확인할 점

  1. 저장한 HTML에서 위로 이동할 목표 요소를 찾는다.
  2. 목표 요소에 id="up"을 지정한다.
  3. 클릭할 글자나 이미지를 a 요소로 감싼다.
  4. href="#up"을 지정하고 저장한다.
  5. 브라우저에서 수정된 페이지를 다시 열거나 새로고침한다.
  6. 링크를 눌러 지정한 제목·이미지로 이동하는지 확인한다.
  • id 값과 href의 # 뒤 이름이 정확히 같은지 확인한다.
  • 하나의 문서에 같은 id를 두 번 사용하지 않는다.
  • 이미지 링크는 a의 시작·종료 태그가 img를 제대로 감싸는지 확인한다.
  • 도착점이 페이지 맨 위인지, 본문 중간인지 구분한다.
  • 저장된 큰 웹페이지는 HTML·CSS·JavaScript의 역할을 나누어 살펴본다.

07 / QUICK REVIEW

원리를 다시 확인하기

절대 주소와 상대 주소는 어떤 기준으로 구분하는가?

절대 주소는 전체 주소를 지정한다. 상대 주소는 현재 문서의 위치를 기준으로 파일이나 경로를 찾는다.

alt와 title은 같은 역할인가?

alt는 이미지 대신 전달할 내용을 나타낸다. title은 보조 설명이며 읽기 쉬운 링크 텍스트나 이미지의 대체 텍스트를 대신하지 않는다.

figcaption은 어디에 작성하는가?

figure 안에서 콘텐츠의 설명으로 작성한다. 이미지 링크는 a가 img를 감싸도록 하고 설명은 같은 figure 안에 배치한다.

id에는 #up을 쓰는가, up을 쓰는가?

id="up"으로 쓰고, 이동할 링크에서 href="#up"으로 쓴다.

<a>만 감싸면 이동 기능이 생기는가?

href로 이동할 대상을 지정해야 한다. href 없는 a에는 이 실습의 이동 주소가 없다.

up이라는 이름은 페이지의 맨 위를 뜻하는가?

개발자가 정한 id 이름이다. id="up"인 요소가 실제로 놓인 위치로 이동한다.

이미지를 눌러도 이동할 수 있는가?

a href="#up" 안에 img를 넣으면 이미지가 링크의 클릭 영역이 된다.

href="#up"과 window.scrollTo(0, 0)은 같은가?

전자는 이름으로 지정한 요소를 찾고, 후자는 페이지의 좌표로 이동한다. 목표 요소가 중간에 있으면 도착 위치가 다를 수 있다.
